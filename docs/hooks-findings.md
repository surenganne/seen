# Phase 0 findings: Claude Code hooks

Recorded 2026-10-18 against **Claude Code 2.1.302**, model `claude-sonnet-5-5`, macOS.
Method: a throwaway recorder plugin (`spikes/recorder/`) loaded with
`claude -p --plugin-dir spikes/recorder --setting-sources project`, run in scratch
git repos. Each experiment is a separate headless session. Scrubbed payloads are in
`tests/fixtures/hook_payloads/`, scrubbed transcripts in `tests/fixtures/transcripts/`
(regenerate with `spikes/scrub_fixtures.py`).

## Assumption status

| ID | Status | Evidence and notes |
|---|---|---|
| A1 | **Confirmed** | `hooks/hooks.json` with the `{"hooks":{...}}` wrapper loads from `--plugin-dir` and from a marketplace install. Every payload has `session_id`, `transcript_path`, `cwd`, `hook_event_name`. Tool events add `tool_name`, `tool_input`, `tool_use_id`; PostToolUse adds `tool_response` and `duration_ms`. **New fields:** `prompt_id` on every event after the first prompt (a stable turn id), `permission_mode`, `effort`. `CLAUDE_PLUGIN_ROOT` and `CLAUDE_PROJECT_DIR` are set in the hook env. |
| A2 | **Confirmed** | Stop payload has `stop_hook_active` (false, then true on the forced continuation). Stdout `{"decision":"block","reason":"..."}` with exit 0 makes Claude continue; the model ran the named skill, then stopped. No loop when the guard is honoured. Stop also carries **`last_assistant_message`**, so the summary (9.4) needs no transcript read. A `stop-hook-error` notification is emitted to the stream on a block, which is cosmetic. |
| A3 | **Confirmed, with a change** | Assistant lines carry `message.id`, `message.model`, and `message.usage` with `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`. No duplicates in these runs; dedupe by `message.id` anyway. **Change:** subagent usage is NOT in the main transcript. It lives in `<transcript without .jsonl>/subagents/agent-<id>.jsonl`. Main plus subagent files reconcile exactly to native totals (see A8). Each line also has `promptId`, which matches the hook's `prompt_id`. |
| A4 | **Confirmed** | Model-invoked skills appear as `PreToolUse`/`PostToolUse` with `tool_name: "Skill"` and `tool_input.skill: "<name>"` (plugin skills are `plugin:skill`), and as `tool_use` blocks named `Skill` in the transcript. **Slash-invoked skills fire no Skill tool event.** They show only as `prompt: "/greet-skill"` in UserPromptSubmit and as `<command-name>/greet-skill</command-name>` in the transcript. Skills run inside a subagent fire the same hooks, with `agent_id` and `agent_type` in the payload, which gives trigger `subagent`. Recall on a scripted run: 11/11 Skill tool calls seen by hooks and by the transcript, plus 1/1 slash and 1/1 subagent, i.e. 13/13 (100%). |
| A5 | **Confirmed, both formats work** | SessionStart and UserPromptSubmit: plain stdout (exit 0) and `{"hookSpecificOutput":{"hookEventName":"<Event>","additionalContext":"..."}}` both reach the model. Proof: the model answered with both injected codewords. **Seen uses the JSON form** (explicit, and it composes with `systemMessage`). |
| A6 | **Confirmed** | PreToolUse exit 2 with stderr blocks `Edit`, `Write` and `NotebookEdit`. The model sees `PreToolUse:<Tool> hook error: [...]: <stderr>`. The model recovered by calling `Write` on an allowed path. **`MultiEdit` does not exist in 2.1.302** (absent from the tool list). Keep it in the matcher, which is harmless. NotebookEdit's path key is `notebook_path`, not `file_path`. |
| A7 | **Confirmed** | Implemented in P1-8 (`seen_core.skills.hashing`) with tests: stable across runs, changes when a bundled script changes, ignores `.git`/`node_modules`/`__pycache__`/`.DS_Store`, skips symlinks escaping the folder. |
| A8 | **Confirmed (0% gap)** | Summing deduped transcript usage (main plus subagent files) equals Claude Code's native `cost-state.modelUsage` exactly in four sessions, e.g. in=10 out=454 cache_read=64311 cache_write=25415. The OTel console exporter printed nothing in `-p` mode, so the native reference is the transcript's own `cost-state` line (same counters that feed OTel). `cost-state` also carries `costUSD` per model, which is a check on `pricing/prices.json`. |
| A9 | **Confirmed** | (a) `claude plugin marketplace add ./path` then `claude plugin install seen@seen-tools` works (user scope). (b) A repo `.claude/settings.json` with `extraKnownMarketplaces` (`{"source":{"source":"directory","path":...}}` or a github source) plus `enabledPlugins: {"seen@seen-tools": true}` auto-installs the plugin **only after the workspace is trusted**; untrusted workspaces silently skip it. `file://` git URLs are rejected as a marketplace source; use `owner/repo`, `https://…`, or a path. Tested with an isolated `CLAUDE_CONFIG_DIR`, so the real `~/.claude` was not touched. |
| A10 | **Confirmed, with nuance** | The transcript holds what the **model saw**: Read results (numbered lines), Bash stdout, MCP results (full), and WebFetch's processed result (not the raw page). Large Bash output (195 KB) is replaced in context by a `<persisted-output>` preview of about 2 KB; the hook's `tool_response.stdout` holds about 30 KB; the full output goes to a side file. Scanning the transcript slice therefore scans what reached the model. |
| A11 | **Confirmed** | UserPromptSubmit exit 2: the prompt is blocked, the stderr and the original prompt are shown to the user, and the model never runs. `{"systemMessage": "..."}` on stdout: the model did **not** see it (it answered "No"). It is surfaced to the user (the stream shows it in the hook response). |
| A12 | **Confirmed** | PreToolUse exit 2 on `Read` denies the read before content enters context. The model sees the stderr reason. |

**Gate check:** A4 holds and A8 has a 0% gap, so Phase 1 may start.

## Other facts recorded

- **Hook latency (P0-10):** cold `python3` stdlib process: p50 48 ms, p95 50 ms (no-op); recorder that writes a file: p50 58 ms, p95 61 ms. `git diff --numstat` p95 14 ms. Under the 100 ms target, so no zipapp fallback is needed.
- **Memory writes (P0-11):** in `default` permission mode, writing `.seen/memory/x.md` **prompts for permission** (denied in `-p`). With `permissions.allow: ["Write(.seen/memory/**)","Edit(.seen/memory/**)"]` it succeeds with no prompt. `seen init` therefore adds these two allow rules to the repo's `.claude/settings.json`. Project `permissions.allow` is ignored until the workspace is trusted.
- **Deny syntax (P0-13):** `permissions.deny: ["Read(./src/secret_patients.csv)"]` blocks the Read tool. The model sees `File is in a directory that is denied by your permission settings.` A denied call **does not reach PreToolUse hooks**. A Read deny does **not** stop `cat` through Bash, so the deny-list snippet should pair `Read(./path)` with a note.
- **Transcript noise:** besides `user`/`assistant`/`system`, transcripts contain `attachment`, `api-request*`, `queue-operation`, `last-prompt`, `atis-latch` and `cost-state` lines. **`attachment` lines include Claude Code's own injected context (environment, skill listing, and the user's email in `session_context`).** The Stop-time PII scan must scan only `user` text, `tool_result` and `tool_use` input, and Seen's own injected memory. Otherwise every turn reports the developer's own email.
- **Skill body injection:** after a Skill call the transcript has a `user` line with `isMeta: true` beginning `Base directory for this skill: <path>`, which gives the skill folder path.
- **Claude Code version:** not in hook payloads. Every transcript line has `version`. SessionStart reads it lazily, at ingest.
- **Sideloaded plugins:** hook payloads carry no plugin list (only the `-p` stream `init` event does). Seen marks an invoked skill as `sideload` when its name is not in the scanned inventory.
- **Managed (org) skill folder:** `/Library/Application Support/ClaudeCode/` on macOS (`/etc/claude-code/` on Linux). Not present on the dev machine. The scanner checks it when it exists.
- **Stop fires once per turn;** SessionEnd payload has `reason` (`other` in `-p` mode). SubagentStop carries `agent_transcript_path`.
- **Entrypoint (spikes/entrypoint):** hooks inherit `CLAUDE_CODE_ENTRYPOINT`: `cli` for an interactive session, `sdk-cli` for `claude -p`, `sdk-py`/`sdk-ts` for the Agent SDK. Plugins that run background agents (reflectors, summarisers) start `sdk-*` sessions in the repo's folder, so they fire Seen's hooks too. Transcript lines carry the same value as `entrypoint`.
