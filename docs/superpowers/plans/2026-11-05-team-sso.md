# Team SSO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace hand-minted team API keys with single sign-on: a person signs in with the company IdP, and the team server issues them a key bound to their verified identity and a role.

**Architecture:** The team server validates an OIDC `id_token` (auth-code + PKCE, run from the CLI or the local dashboard through a loopback redirect), upserts a `team_users` row, and mints an ordinary hashed `TeamApiKey` (30-day expiry, `origin="sso"`). Everything downstream (`seen sync`, the dashboard proxy, role checks) keeps using Bearer keys. No browser token storage, no session-signing key, no client secret.

**Tech Stack:** FastAPI, PyJWT with `cryptography` (new dependency for `seen-team` only), stdlib `http.server`/`urllib` on the client, existing SQLAlchemy models.

**Spec:** None written. Design calls are under "Calls made". Reference: `/Users/surendraganne/repos/bedrock-gateway` (`app/auth/oidc.py`, `docs/authentication.md`). It is a bearer-token OIDC gateway. Its JWKS cache with one refresh on a `kid` miss, audience check, email-domain allowlist and role lookup are reused as ideas. Its implicit flow with `localStorage`, DB-stored signing key and plain-env admin password are not.

**Relationship to the dashboard plan:** `2026-11-05-team-dashboard.md` assumes a key from the environment. After this plan its key comes from `seen team login`. Build this plan first, or at least SSO-0 to SSO-2.

## Calls made (owner to confirm)

- **IdP:** one OIDC provider per team server, set by env. I assume Microsoft Entra ID (your stack is Microsoft 365). Any OIDC issuer works.
- **Flow:** authorization code + PKCE (S256), public client, loopback redirect. The IdP app registration is "mobile and desktop / public client" with `http://127.0.0.1` redirect URIs.
- **Roles (v1):** `member` (push own changes only), `lead` (read every project's aggregates and the members list), `admin` (everything, manages users). Admins come from `SEEN_TEAM_ADMINS`; everyone else starts as `member`; an admin promotes leads. **Project-scoped leads are not in v1** (decision for you).
- **Who can sign in:** emails whose domain is in `SEEN_OIDC_ALLOWED_DOMAINS` and whose token says the email is verified (when the claim is present).
- **Stored identity:** `team_users(sub, email, role, active, first_seen, last_login)`. The email is plaintext PII under DPDP, so it is a recorded decision item (see Global Constraints). It exists so leads can read who has synced.
- **Key at rest on the client:** `~/.seen/team_key`, mode 0600, same trust level as `secret.key`. OS keychain is the alternative, deferred.
- **Break-glass:** the bootstrap key stays but `SEEN_TEAM_BOOTSTRAP_DISABLE=1` turns it off once an SSO admin exists.

## Global Constraints

- Never log, store or echo an `id_token`, authorization code, PKCE verifier or API key. Fixed error strings only.
- Production guard (`APP_ENV=production`): the server refuses to start if `SEEN_OIDC_ISSUER`, `SEEN_OIDC_CLIENT_ID` or `SEEN_OIDC_ALLOWED_DOMAINS` is missing, unlike the gateway, which skips the audience check when unset.
- Only `RS256` tokens. Reject `none`, `HS*`, and any alg not on the allowlist.
- The client sends credentials only over https, or http to `localhost`/`127.0.0.1`/`::1` (reuse the `sync._server` rule).
- Config key names: `SEEN_OIDC_ISSUER`, `SEEN_OIDC_CLIENT_ID`, `SEEN_OIDC_ALLOWED_DOMAINS`, `SEEN_TEAM_ADMINS`, `SEEN_TEAM_BOOTSTRAP_DISABLE`. Secrets-bearing values go through Secrets Manager in deployment, not plain container env.
- Repo rules from `CLAUDE.md`: write through `seen_core.safeio`; hooks stay stdlib-only and untouched; never UPDATE or DELETE audit rows; ports as documented.
- Schema changes on the team server follow the existing `_add_missing_key_columns` mechanism (there is no Alembic there yet).
- Gates: `uv run ruff check . && uv run mypy packages/core/src && uv run pytest`, `uv run python scripts/gen_openapi.py --check`; `uv run pip-audit` after adding the dependency. Commits name the task ID (`SSO-0` ... `SSO-4`).

## Review Focus

1. **Token attacks:** `alg: none`, an HS256 token signed with the IdP's public key as the secret, wrong `iss`, wrong `aud`, expired, not-yet-valid, and a missing or wrong `nonce` all give 401, never 500.
2. **Email domain matching:** `evil-minfytech.com`, `minfytech.com.evil.io`, `user@MINFYTECH.COM` (case) and an address with two `@`. Only an exact domain match is accepted.
3. **Deactivation and expiry are immediate:** an `active=false` user's existing keys stop working on the next request, and a 30-day key stops at expiry with a message that says to run `seen team login`.
4. **Callback abuse:** replayed, expired (over 10 minutes) or mismatched `state` is refused. The callback always redirects to the fixed path `/team`, never to a supplied URL.
5. **Key leakage to disk or snapshots:** `team_key` is mode 0600, is excluded by `seen docker-sync`, and is removed by `seen team logout`.

### Task 1: SSO-1 Users, exchange endpoint, roles (team server)

**Files:**
- Modify: `packages/team_server/src/seen_team/models.py` (add `TeamUser`; add `origin: str` default `"manual"` to `TeamApiKey`), `packages/team_server/src/seen_team/app.py`
- Test: `tests/team/test_sso.py`

**Interfaces:**
- Consumes: `validate_id_token`, `OidcConfig`, `Identity` from SSO-0.
- Produces:
  - `TeamUser{sub: str (pk), email: str, role: Literal["member","lead","admin"], active: bool, first_seen: str, last_login: str}`.
  - `POST /auth/exchange` body `{id_token: str, nonce: str}` returns `{key: str, expires_at: str, email: str, role: str}`. It is pre-auth, so it uses the existing per-IP limiter and counts failures. A first-time email in `SEEN_TEAM_ADMINS` becomes `admin`, anyone else `member`. The minted `TeamApiKey` has `origin="sso"`, `user_id` set to `TeamUser.sub`, `project_id=None`, 30-day `expires_at`, and its role is copied from the user row at mint time.
  - `PUT /api/users/{sub}` (admin only) body `{role?: ..., active?: bool}`.
  - `GET /api/users` (admin only) returns `[{sub, email, role, active, last_login}]`.
  - `auth()` also returns 401 when the key's `TeamUser` is inactive, and re-reads the role from `TeamUser` (so a demotion takes effect immediately).
  - `can_see(k, pid)`: unchanged for manual keys; for `origin == "sso"` keys, `lead` and `admin` may read any project.
  - `sync`: for `origin == "sso"` keys the server stores `user_id = k.user_id` and ignores the client-sent value (today it returns 403 on mismatch; keep that for manual keys).
  - `SEEN_TEAM_BOOTSTRAP_DISABLE=1` makes the bootstrap-key branch in `auth()` unreachable.
  - The members route from the dashboard plan (TD-0) additionally returns `email` for `origin == "sso"` users.
